Syncing flagged miscategorisations to GitHub

Executive brief · 25 October 2026 · for the live site at mikrishnan.github.io/kant-lab

Bottom line

Yes, it's possible, but the page can't do it alone. GitHub Pages only serves files. A page running in a reader's browser has no permission to change the repository. Today's button writes to a file on your own computer, and on the live site there is no such file.

Recommended: let GitHub do the writing. The button opens a filled-in GitHub issue. A GitHub Action, a small script GitHub runs for the repository, checks it and opens a pull request that adds the flags to miscategorisations.js. Once that's merged, every visitor sees the flags. Readers never handle a password, and there is no server to run.

How it works

The three ways to do it

A · Issue, then Action

Recommended
  • No password or key in the page
  • No server; everything stays on GitHub
  • Fits the repo's workflow: issue, pull request, merge
  • Each flag leaves a record you can trace
  • One extra click (Submit), and a GitHub account

B · A token in the browser

Only for you alone
  • One click, straight to GitHub
  • Each flagger pastes a personal access token with write access
  • A leaked token can change the whole repository
  • Protected main still forces a pull request

C · A small server

Not advised
  • One click, no GitHub account needed
  • An outside service and a secret key to look after
  • Breaks the repository's no-server design
  • Needs its own spam protection

Safeguards and limits

Safeguards built in

  • The Action reads the issue as data and never runs it as code.
  • Every flag must name a real example whose categorisation matches the file. Anything else is rejected with a comment on the issue.
  • Duplicate flags are ignored.
  • Only people signed in to GitHub can file, and every change arrives as a pull request you can turn down.

Limits to know

  • "Automatic" starts after the reader presses Submit on GitHub.
  • A filled-in link holds only a handful of flags. For more, the page copies them for pasting into the form.
  • Whether a pull request can merge with no click depends on main's protection rules. I can't see those from here.
  • After a merge, the live site takes a few minutes to update.

# Puzzles

A running list of hunches about the kinds of nothing that are not yet requests. Each is a
place where something seems to have an order we cannot see yet, or where the data might one
day help, before anyone knows what to ask of it. Anyone in the seminar with GitHub access can
add a puzzle, or add to one, and the list grows as the ideas do.

## Adding to it

- **Say it to Claude,** in any session on this repository, at
  [claude.ai/code](https://claude.ai/code) or in the desktop app:

  > Puzzle: *nichts*, *Negation* and *verneinend* sound alike but differ; we suspect an order.

  To add to one already here:

  > On puzzle 1: …

  You can also just think aloud and say it is for the puzzles. Claude puts it under the
  puzzle it belongs to, or starts a new one, and tells you which. Then it opens a pull
  request, which you merge yourself.
- **Or edit this file on github.com.** Press the pencil, add your entry, choose **Create a
  new branch for this commit and start a pull request**, then **Squash and merge**.

Nobody needs to approve a change here. If two people add at once and GitHub reports a
conflict, close the later pull request and add the entry again. It takes a minute.

## How it is kept

Every Claude session follows these rules here, and people adding by hand are asked to as well.

1. **Your words.** An entry keeps what the person said, trimmed only of filler words and
   false starts. It is not summarised, reworded, or tidied into a question.
2. **Nothing is suggested unless someone asks.** Writing a hunch down is not an invitation to
   propose an analysis, a tool or a reading. If someone does ask, Claude's answer goes in as a
   development of its own, headed **Claude, asked by** and the username, so that it can never
   pass for a participant's thought.
3. **Nothing is overwritten.** A puzzle grows by dated developments added at its end. An
   earlier entry is never edited or deleted, least of all someone else's; a change of mind is
   a new development.
4. **Who and when.** Every entry carries the date and the GitHub username of whoever said it.
   The repository is public, so it holds usernames, not names. Claude asks for the username
   when it does not know it.
5. **Numbers never move.** A new puzzle takes the next number. A dropped one stays where it
   is, struck through, with the date and the reason.
6. **Each puzzle has a status**, and a change of status is itself a development, with who and
   when:
   - *noticed*: written down, nothing more;
   - *ready to ask*: someone now knows what they would want;
   - *became a request*: it turned into a feature, linked here;
   - *dropped*.
7. **Where it goes.** If a development could belong to more than one puzzle, or to none,
   Claude says which it chose, so the person can move it.

A new puzzle, at the end of the file:

```
### N. A few words naming it

**Status:** noticed · raised <date> by <username>

> The hunch, in the words it was said in.

**Prompted by:** words, passages or portal links, if any

**Developments**

- <date>, <username>: …
```
